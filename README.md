# advanced-cryptography-note

[zk-tokyo Advanced Cryptography Program 2026](https://github.com/zk-tokyo/advanced-cryptography-2026) を
受講しながら書いている、**個人の自習ノート**です。公式教材ではありません。

各週のノートは単一の HTML ファイルで、外部通信もビルドも不要です。ブラウザで開けば動きます。

**目次ページ: [`index.html`](index.html)** — 週の一覧、各ノートの進み方、教材としての方針。

## 教材としての方針

ブログ記事は読み物として書きますが、こちらは繰り返し戻ってくる教材として、次の 3 層で組んでいます。

1. **前提から** — 手順ではなく「そもそもなぜその道具が要るのか」から書く
2. **壊せるラボ** — 正しい完成形だけでは各行が何を買っているか分からないので、1 行外して壊す
3. **検問クイズ** — 出題はその場で生成。判定はラボと同じ計算器が行うので、答えを覚えても意味がない

### Week 0（土台編）に入っているもの

- **前提から**: 普通の整数のままでは何が困るのか → 四則が全部できて有限で大小の手がかりがない世界がほしい → 有限体
- **群・環・体**: 何が使えるかの階層。Z/6Z で 2·3 = 0 になる（零因子）ことが、法が素数でなければならない理由そのもの
- **逆元**: 総当たり／フェルマーの小定理／拡張ユークリッドの 3 通りを、途中式と演算回数つきで比較
- **楕円曲線**: 点の足し算がなぜ群になるのか、加法公式、double-and-add
- **対話型ラボ 2 つ**: 法を切り替えると乗法表の零因子が現れる／消える電卓（逆元を 3 方式で計算）／曲線の全点を描いて巡回を辿り、離散対数を総当たりで解いて試行回数を見るラボ
- **検問クイズ**: mod 計算・逆元・体の判定・群の性質・楕円曲線・原理の 6 分野

### Week 1 に入っているもの

- **前提から**: 素朴な方法がなぜ全部壊れるか → 暗号が貸してくれる演算は + と × だけ → その翻訳結果が算術回路
- **プライバシーの仕組み**: コミットメントという「箱」、箱のまま足し算できること、なぜ回路単体では何も隠れないのか
- **ZK / MPC / FHE**: それぞれ何を解く技術なのか、なぜ同じ土台を共有するのか
- **対話型ラボ**: 8 本の制約を 1 本ずつ外して回路を壊せる。権限のない 494 通りの資格を総当たりして「何通り通ってしまうか」をその場で計算する
- **検問クイズ**: 出題は毎回生成され、判定はラボと同じ計算器が行う。ライフ 3・10 問・S/A/B/F ランク
- **現場の道具**: Circom の `<--`、Noir の `unconstrained` に、同じバグがどう現れるか

### Week 2 に入っているもの

- **前提から**: 「持ち寄りたいが見せたくない」を素朴に解くとなぜ壊れるか → 秘密分散（Shamir と、課題で使う加法的版）
- **壊した実測**: 公開項 `d·e` を全員が足すと復元がずれる／積は全部正しいのに開示回数 4 ≠ 2 で落ちる実装／Beaver triple を再利用すると公開値だけから `x₁ − x₂` が復元できる — いずれも公式課題の採点器に通した実際の出力つき
- **ビットの世界**: XOR シェア、1-out-of-2 紛失通信（OT）のトイ構成（なぜ receiver secret に 0 を含めるのかの分布実測込み）、OT 2 回で AND を作る GMW
- **対話型ラボ 2 つ**: シェアを配って復元する Shamir ラボ／OT の鍵導出まで見える GMW 実行トレース
- **検問クイズ**: シェア計算・Beaver 検算・開示監査・OT 検問・GMW 検算・原理の 6 分野。ライフ 3・10 問・S/A/B/F ランク

### Week 3 に入っているもの

- **講義スライド「zkSNARK part 1」65 枚と同じ順番のカード列**（1 カード = スライド 1〜2 枚 = 主張 1 つ + 式か例 1 個）。宿題 `schnorr-from-scratch` の 10 個の関数がスライドのどこに当たるかを毎回「宿題ではここ」で示す
- **講義が飛ばした 2 歩を専用カード群で**: (1) 制約 → 多項式 → 短い証明を F₁₇ の R1CS 3 行で最後まで（補間・因数定理・ランダム 1 点、嘘は割り切れない、Z_H·r のマスクでゼロ知識化）、(2) ゼロ知識証明を自分で組み立てる 5 手順（隠す手は「乱数で覆う」と「聞かれた分だけ開ける」の 2 つ、完全性・健全性・ゼロ知識は 3 つの問いで確かめる。数独・Schnorr・3 彩色を同じ表で）
- **宿題の関数 ↔ スライド ↔ 学校で習ったこと** の対応表と、提出前の自己チェック 7 問
- **対話型ラボ 2 つ**: 正直な証明者と simulator を切り替えて 3 手を回すラボ／nonce 再利用で秘密鍵を復元する攻撃ラボ
- **検問クイズ**: 有限体・楕円曲線・レスポンス計算・受理判定・鍵復元・原理の 6 分野
- **付録（旧版の本文）**: 壊した採点結果、ペアリング・FFT・R1CS/AIR の具体例、数独 ZKP を開閉式で

### Week 4 に入っているもの

- **前提から**: Week 3 の Schnorr の 3 手を 1 枚にして「何を渡していたのか」から始める。署名とゼロ知識証明の違い、証明の 5 パート、計算複雑性（P / NP、3 彩色を 59049 通り総当たり vs 辺 15 本の検証）、NP に対話・ランダム性・オラクルを足すと IP / PCP / IOP になる理由
- **3 部品表**: 算術化・コミットメント・証明システム。GKR / STARK / PLONK を同じトイ計算 `f = (x₁+x₂) + (x₃·x₄)` で 3 通りに翻訳し、講義の数値をすべて再計算
- **壊した実測**: SumCheck の嘘の主張は 121 通り中 21 通りしか通らない／トレースを 1 マス改ざんすると制約多項式が Z_H で割り切れず、点ごとに割った値を補間すると次数 2 → 7 に跳ねる／PLONK でゲート制約を全部満たしても配線が違う witness は大積で落ちる（F₁₀₁ で見逃し 6.7%）
- **対話型ラボ 3 つ**: 検証者として r₁, r₂ を選ぶ SumCheck ラボ（121 通りの受理地図つき）／トレースのマスを書き換えて商多項式と FRI の折り畳みを見る STARK ラボ（制約の無いマス = アンダー制約も体験できる）／ゲート表を書き換えてゲート制約・コピー制約・大積を同時に見る PLONK ラボ
- **ゼロ知識化**: ブラインド多項式 f + Z_H·R の数値例、セレクターをブラインドしない理由、GKR でマスクとコミットの両方が要る理由
- **同じ物差し**: 計算量・証明サイズ・信頼設定・仮定の比較表（講義で伏せられた Q への自分の答え）と、ワークショップ「ZK, or not ZK（AI エージェント保険）」の考え方
- **検問クイズ**: 証明システム・SumCheck・AIR / 商・FRI・PLONK・原理の 6 分野。出題は毎回生成、判定はラボと同じ計算器
