# advanced-cryptography-note

[zk-tokyo Advanced Cryptography Program 2026](https://github.com/zk-tokyo/advanced-cryptography-2026) を
受講しながら書いている、**個人の自習ノート**です。公式教材ではありません。

各週のノートは単一の HTML ファイルで、外部通信もビルドも不要です。ブラウザで開けば動きます。

**目次ページ: [`index.html`](index.html)** — 週の一覧、各ノートの進み方、教材としての方針。

## 教材としての方針

ブログ記事は読み物として書きますが、こちらは繰り返し戻ってくる教材として、次の 3 層で組んでいます。

1. **前提から** — 手順ではなく「そもそもなぜその道具が要るのか」から書く
2. **壊せるラボ** — 正しい完成形だけでは各行が何を買っているか分からないので、1 行外して壊す
3. **検問クイズ** — 出題はその場で生成。判定はラボと同じ計算器が行うので、答えを覚えても意味がない

### Week 1 に入っているもの

- **前提から**: 素朴な方法がなぜ全部壊れるか → 暗号が貸してくれる演算は + と × だけ → その翻訳結果が算術回路
- **プライバシーの仕組み**: コミットメントという「箱」、箱のまま足し算できること、なぜ回路単体では何も隠れないのか
- **ZK / MPC / FHE**: それぞれ何を解く技術なのか、なぜ同じ土台を共有するのか
- **対話型ラボ**: 8 本の制約を 1 本ずつ外して回路を壊せる。権限のない 494 通りの資格を総当たりして「何通り通ってしまうか」をその場で計算する
- **検問クイズ**: 出題は毎回生成され、判定はラボと同じ計算器が行う。ライフ 3・10 問・S/A/B/F ランク
- **現場の道具**: Circom の `<--`、Noir の `unconstrained` に、同じバグがどう現れるか

### Week 2 に入っているもの

- **前提から**: 「持ち寄りたいが見せたくない」を素朴に解くとなぜ壊れるか → 秘密分散（Shamir と、課題で使う加法的版）
- **壊した実測**: 公開項 `d·e` を全員が足すと復元がずれる／積は全部正しいのに開示回数 4 ≠ 2 で落ちる実装／Beaver triple を再利用すると公開値だけから `x₁ − x₂` が復元できる — いずれも公式課題の採点器に通した実際の出力つき
- **ビットの世界**: XOR シェア、1-out-of-2 紛失通信（OT）のトイ構成（なぜ receiver secret に 0 を含めるのかの分布実測込み）、OT 2 回で AND を作る GMW
- **対話型ラボ 2 つ**: シェアを配って復元する Shamir ラボ／OT の鍵導出まで見える GMW 実行トレース
- **検問クイズ**: シェア計算・Beaver 検算・開示監査・OT 検問・GMW 検算・原理の 6 分野。ライフ 3・10 問・S/A/B/F ランク

### Week 3 に入っているもの

- **前提から**: 週 README（楕円曲線と Schnorr）と講義スライド（zkSNARK part 1）が別トピックに見える理由 — 同じパイプラインの違う場所を指している
- **積み上げ**: 有限体の逆元（拡張ユークリッド）→ 点の加法公式 → double-and-add → 離散対数 → シグマプロトコル → Fiat-Shamir
- **壊した実測**: 逆元の正規化忘れ／y 座標の符号ミスで点が曲線から落ちる／素朴なスカラー倍では約 3.0×10^63 年かかる／mod n と mod p の取り違えは「小さい値のときだけ通る」／ハッシュの引数順ミス — すべて公式採点器の実出力つき
- **対話型ラボ 2 つ**: 正直な証明者と simulator を切り替えて 3 手を回すラボ（どちらも受理されることを確認できる）／nonce 再利用で秘密鍵を復元する攻撃ラボ
- **検問クイズ**: 有限体・楕円曲線・レスポンス計算・受理判定・鍵復元・原理の 6 分野
- **地図**: スライド後半（多項式とフーリエ、commitment、KZG、ペアリング、R1CS と AIR）を Week 4 以降への見取り図として

## ネタバレについて

各週のノートには、その週の課題の**答え（に相当するプロトコルの中身）が含まれます**
（Week 1 は `proof-of-exploit`、Week 2 は `toy-mpc`、Week 3 は `schnorr-from-scratch`）。
自分で解いてから読むことをおすすめします。

（なお公式リポジトリの提出は公開 Pull Request で行われるため、各人の解答はもともと公開されています。）

## 数値について

ノート内の数値は、公式リポジトリの採点器を実際に走らせて突き合わせています
（Week 1: `proof-of-exploit` の solver、Week 2 と Week 3: 公開テストにわざと壊した実装を通した出力）。
ページ内のラボと検問クイズの計算はすべてブラウザ内で行われ、外部への通信はありません。
