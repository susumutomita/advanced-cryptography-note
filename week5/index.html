Advanced Cryptography Noteスライドとの対応

Advanced Cryptography Program 2026 / Week 5

暗号文のまま
プログラムを動かす

この週は FHE・LWE・RLWE・RGSW・CMUX・Blind Rotation という単語を覚える週ではない。最終ゴールは一つだけ。秘密の入力を復号せずにプログラムを実行し、暗号化された結果を返すこと。各部品は、そのゴールへ進む途中で生まれた問題を解くために登場する。

0 / 最終ゴール

まず到達点を固定する

Dec(Eval(f, Enc(m))) = f(m)

入力 m をクラウドへ見せず、クラウドが関数 f を実行し、最後に鍵を持つ人だけが f(m) を得る。FHE は「強い暗号」ではなく、暗号文の世界に計算機を作る技術と考える。

秘密の入力 m
    ↓ 暗号化
  Enc(m)
    ↓
    ↓ クラウドが中身を見ずにプログラム f を実行
    ↓
 Enc(f(m))
    ↓ 復号
   f(m)
Week 5 の一本線
暗号文のままプログラム → NAND → 関数表 → 多項式回転 → RLWE → 秘密のまま回転 → PBS → HomNAND → NAND を組み合わせてプログラム。

1 / ストーリー

各用語は「前の問題を解くため」にだけ登場する

01

暗号文のままプログラムを実行したい

普通の暗号は秘密を隠せるが、通常は復号しないと計算できない。

02

プログラムを論理ゲートへ分解する

NAND だけで任意の Boolean 回路を構成できる。したがって暗号文のまま NAND ができれば、理論上プログラムへ進める。

03

まず LWE で「秘密の値を計算可能な形で運ぶ」

暗号文同士の加算などを行える。ただし計算すると noise が増え、いつか復号が壊れる。

04

任意の関数を「表引き」として考える

f(0), f(1), ... を並べ、秘密の入力に対応する場所を先頭へ持ってくればよい。

05

表を回すため、多項式へ移る → RLWE

多項式に X^k を掛けると係数が回転する。これが TFHE の表引きの土台になる。

06

しかし回転量に秘密鍵が入っている

入力位置に相当する量は b - <a,s>。クラウドは秘密鍵 s を知らない。

07

RGSW + CMUX で秘密鍵を見ずに選択する

秘密鍵ビットが 0 か 1 かを見ずに「回す / 回さない」を選び、Blind Rotation を構成する。

08

Blind Rotation で関数表を秘密の位置まで回す

暗号化された入力が指す位置の関数値を定数項へ運ぶ。

09

Sample Extraction で答え 1 個を LWE として抜く

回転結果は RLWE。アプリケーション側で扱いやすい LWE 暗号文へ戻す。

10

Key Switching で元の鍵へ戻す

途中処理で変わった秘密鍵ドメインを、平文を変えずに元へ戻す。

11

全部つなぐ → Programmable Bootstrapping

Enc(m) → Enc(f(m)) を行いながら noise も新しくする。

12

関数として NAND を選ぶ → HomNAND

NAND を繰り返せば暗号文上の一般的な Boolean プログラムへ到達する。

2 / 代数の世界

Week 5 は「有限体の暗号」ではない

Week 3/4 では有限体が主役だったため混同しやすい。しかし TFHE の説明で主に使うのは、整数の剰余環と多項式剰余環である。

整数側

Z_q

q が素数なら体になるが、講義例の q=32,64 のように合成数なら体ではない。それでも加算・乗算ができる「環」。

→

多項式側

R_q = Z_q[X] / (X^N + 1)

係数は mod q、多項式は X^N+1 で割った余りとして扱う。

3 / LWE

LWE は「秘密の値 + mask + noise」の最小モデル

b = <a,s> + Δm + e    (mod q)
記号意味なぜ必要か
m秘密にしたい平文最終的に計算したい値
Δm平文を離れた目盛りへ置く小さな noise があっても隣の値と区別する
<a,s>秘密鍵で作る mask鍵を知らない人が平文位置を直接読めないようにする
e小さな誤差LWE の困難性を作る一方、復号可能な限界も生む
qmod q の時計有限な計算空間に閉じる

秘密鍵を知る人は mask を消す。

b - <a,s> = Δm + e

noise が十分小さければ、最も近い Δ の目盛りへ丸めて m を復元できる。

ここでできること: LWE 暗号文同士の加算など、暗号文上の計算を始められる。
ここで足りないこと: 「秘密の入力に応じて任意の関数表を引く」という操作はまだ作れていない。

4 / 関数を表にする

「計算する」を「答えを並べて回す」に変える

例えば次の関数を秘密の入力に適用したい。

f(0) = 7
f(1) = 4
f(2) = 9
f(3) = 1

答えを配列として並べる。

[7, 4, 9, 1]
       ↑ m = 2

入力が 2 なら 2 個ぶん回し、答えを先頭へ持ってくる。

[9, 1, 7, 4]
 ↑
f(2)

TFHE の核心は、秘密の入力についてこの「表引き」を暗号文のまま行うことにある。

5 / なぜ多項式か

多項式の掛け算を「回転装置」として使う

配列を多項式の係数として入れる。

V(X) = a₀ + a₁X + a₂X² + a₃X³

N=4 とし、X⁴ + 1 = 0、つまり X⁴ = -1 の世界で X を掛ける。

X V(X) ≡ -a₃ + a₀X + a₁X² + a₂X³
[a0, a1, a2, a3]
       ↓ × X
[-a3, a0, a1, a2]

掛け算が回転になった。 1 周すると符号が反転するので、この性質を negacyclic と呼ぶ。

RLWE を学ぶ理由はここにある。LWE の式を難しくしたいのではない。関数表を多項式の係数として持ち、X^k を掛けて回転できる計算空間が欲しい。

6 / RLWE — スライド29

「LWE の多項式版」を、目的から読む

スライド29の定義は次の設計図で読む。

LWERLWE
入れ物数・ベクトル多項式
秘密鍵sS(X)
mask<a,s>A(X)S(X)
messageΔmΔμ(X)
noiseeE(X)
計算空間Z_qR_q = Z_q[X]/(X^N+1)
得たい能力暗号文上の基本演算係数操作・回転を含む多項式演算
B(X) = A(X)S(X) + Δμ(X) + E(X)

Gen は何をしている？

秘密鍵をベクトルではなく多項式 S(X) にする。理由は、これから暗号文そのものを多項式演算へ乗せるから。

Enc は何をしている？

LWE と同じ「mask + message + noise」の設計を、多項式環へ移している。

Dec は何をしている？

B(X) - A(X)S(X) = Δμ(X) + E(X)

mask を消し、係数ごとに Δ で丸める。構造は LWE と同じ。

スライド29を読む順番: ① なぜ多項式が必要か → ② X^k が回転になる → ③ その計算空間で LWE と同じ暗号構造を作る → ④ だから RLWE。定義から入ると因果関係が消える。

7 / 次の壁

回転できるようになった。でも「何個回すか」が秘密

LWE の phase は

b - <a,s> = Δm + e

で、入力位置に対応する情報を持つ。しかし右辺を直接求めるには秘密鍵 s が要る。

関数表を回したい
      ↓
何個回す？
      ↓
b - <a,s>
      ↓
秘密鍵 s が必要
      ↓
クラウドへ s は渡せない

そこで「秘密鍵ビットが 0 なら何もしない、1 なら回す」という選択を、ビットそのものを見ずに実行する必要が生まれる。ここで RGSW と CMUX が登場する。

9 / プログラムへ

PBS の関数に NAND を入れると、計算機へ近づく

Boolean 入力 a,b に対して、PBS が NAND を返せるようテスト多項式を設計する。

Enc(a), Enc(b)
      ↓
   HomNAND
      ↓
Enc(NAND(a,b))

NAND は functionally complete なので、NAND を組み合わせれば AND、OR、NOT、比較、加算器、状態機械などの回路を構成できる。

ここがゴール: Week 5 の LWE → RLWE → RGSW → CMUX → Blind Rotation → Sample Extraction → Key Switching は、最終的に「暗号文のままプログラムを動かす」ための実装部品である。

12 / 理解チェック

次へ進む前に、この因果関係を言えるか

FHE の最終ゴールは？Enc(m) → Enc(f(m))。秘密の入力を見せずにプログラムを実行する。
なぜ NAND が出てくる？NAND だけで任意の Boolean 回路を構成できるため。
なぜ LWE の次に RLWE？関数表を多項式の係数へ置き、X^k で回転したいから。
X^N=-1 は何を生む？1 周した係数の符号が反転する negacyclic rotation。
なぜ Blind Rotation？回転量 b-<a,s> に秘密鍵が入るため、値を見ずに回す必要がある。
Sample Extraction はなぜ必要？RLWE の多項式から、欲しい関数値を LWE 暗号文として抜くため。
Key Switching はなぜ必要？途中処理で変わった秘密鍵を、平文を変えず元の鍵へ戻すため。
PBS の意味は？noise を新しくしながら Enc(m) → Enc(f(m)) を行うこと。
スライド29だけを見るときの一文:
「RLWE は LWE を多項式環へ持ち込み、関数表を暗号文のまま回転できるようにするための表現拡張」。まずこの一文を置いてから Gen / Enc / Dec を読む。
